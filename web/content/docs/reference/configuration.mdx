`init` writes `blazeresolver.config.json` at the repo root. The workflow's `fix` job reads it on every run, so commit it. You can edit the commands by hand.

```json title="blazeresolver.config.json"
{
  "repo": "acme/shop",
  "defaultBranch": "main",
  "installCommand": "(cd web && npm ci)",
  "testCommand": "(cd web && npm test)",
  "buildCommand": "(cd web && npm run build)",
  "sandbox": "docker",
  "sandboxImage": "node:22-bookworm-slim",
  "layout": { "frontend": "web", "handler": "next" },
  "installed": {
    "files": ["web/src/app/api/blaze/route.ts", ".github/workflows/blazeresolver.yml", "blazeresolver.config.json"],
    "edits": ["web/src/app/layout.tsx"],
    "dependency": { "dir": "web", "pm": "npm" },
    "env": { "file": "web/.env", "created": true, "added": "..." }
  }
}
```

## Commands

Commands run from the repo root in a shell, so `(cd web && npm test)` and `&&` chains work. In a monorepo `init` chains one command per package that has tests.

**Custom images.** If your tests need more than Node (Python, a browser, native libraries), point `sandboxImage` at an image that has it. Tests still run offline, so everything they need must come from the install step or the image.

**Services.** Tests that need a database or other network service can't reach it from the offline container. Either mock it, or set `"sandbox": "none"` and start the service in the workflow. The audit comment then records that tests ran with network.
