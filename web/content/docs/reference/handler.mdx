```ts
import { createHandler, nodeHandler } from 'blazeresolver/handler';
```

`blazeresolver/handler` ships as both ESM and CommonJS with types, so it works from TypeScript, `import` and `require` alike. The same two functions are also exported from the package root.

## `createHandler(options)`

Returns a Web-standard handler, `(request: Request) => Promise<Response>`. Mount it as-is in Next.js App Router, Cloudflare Workers, Vercel, Deno or Bun.

```ts
const handler = createHandler({
  repo: 'acme/shop',
  allowOrigin: 'https://shop.acme.com',
  rateLimit: { perIp: 5, perHour: 200 },
});
```

## `nodeHandler(handler)`

Adapts a handler to Node's `(req, res)`, for Express, Next.js Pages Router and plain `http` servers. It works with or without a body parser.

```ts
app.all('/api/blaze', nodeHandler(createHandler({ repo: 'acme/shop', allowOrigin: '*' })));
```

## Request body

`POST` with a JSON body, at most 20,000 characters in total. Only `message` is required. Everything else is **repaired rather than rejected**: fields are trimmed, stripped of control characters and cut to their limit, so a customer never loses a report to an overlong field or a mistyped email.

## Responses

| Status | Body | When |
| :--- | :--- | :--- |
| `200` | `{"received": true, "answer": "…"}` | A how-to question, answered from your README and help docs. Nothing is filed. See [Answer questions from your docs](/docs/setup/help-answers). |
| `202` | `{"received": true, "reply": "…"}` | Accepted, with a short plain-text reply to show the customer (written by your AI provider, or a fixed line per kind without one; never the verdict), whatever triage decided: filed bugs and feature requests, grouped duplicates, unanswered questions, and dropped injection attempts |
| `204` | none | `OPTIONS` preflight |
| `400` | `{"error": "invalid json"}` / `{"error": "invalid report"}` | Body isn't JSON, or has no message |
| `405` | `{"error": "POST only"}` | Any other method |
| `413` | `{"error": "too large"}` | Body over 20,000 characters |
| `429` | `{"error": "rate limit"}` | Per-IP or hourly limit hit |
| `500` | `{"error": "BLAZE_GITHUB_TOKEN is not set"}` | No token configured |
| `502` | `{"error": "could not file the report"}` | GitHub refused (expired token, missing permission, GitHub's own limits). Also logged loudly to stderr as `[blazeresolver] could not file a report in <repo>: …`. |

The client IP for rate limiting comes from the first entry of `X-Forwarded-For`.

**Time budget.** Triage gets 8 seconds (then keyword rules decide) and answering a question gets 12, so the handler replies before the widget stops waiting at 25 seconds. Calls to GitHub are retried on rate limits and outages, for at most a few seconds.

## Wrapping the handler

The handler is just a function, so you can put your own logic around it. For example, you could require a signed-in session:

```ts title="app/api/blaze/route.ts"
import { createHandler } from 'blazeresolver/handler';
import { auth } from '@/lib/auth';

const blaze = createHandler({ repo: 'acme/shop' });

export async function POST(req: Request) {
  const session = await auth();
  if (!session) return new Response('Sign in to report a problem', { status: 401 });
  return blaze(req);
}
```
